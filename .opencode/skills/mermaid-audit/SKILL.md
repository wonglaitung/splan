# mermaid-audit：mermaid 图校验与布局修复

本技能用于保证仓库内所有 mermaid 图（`.md` 中的 ` ```mermaid ` 块）**语法可渲染**且**布局合理**。
核心思路：不用肉眼猜，而是用真实的 `mermaid.parse()` 解析器逐块校验；布局问题用「图结构分析」判定，
而非字符串替换。

## 何时使用

- 用户反馈某张 mermaid 图在 GitHub 上「Unable to render」「Parse error」。
- 用户说图「是单列的、很难看」，要求优化。
- 用户要求「同级的节点横放 / 兄弟节点横排」。
- 批量新增/改写文档后，需确认全部 mermaid 图仍能渲染。
- 提交前对全仓库 mermaid 图做一次体检。

## 环境准备（一次性）

脚本在 `scripts/` 下，依赖 `mermaid` + `jsdom`。在脚本目录安装一次即可：

```bash
cd .opencode/skills/mermaid-audit/scripts
npm install mermaid jsdom
```

> Node 需 v18+（用 `node -v` 确认；项目环境为 v22）。安装只需一次，后续直接跑脚本。

## 工作流

### 第一步：全量语法校验

```bash
node scripts/validate.mjs <仓库根目录>
```

脚本会提取全部 ` ```mermaid ` 块，逐一调用 `mermaid.parse()`，输出：
`共发现 mermaid 块: N` 与 `✅ 全部通过` 或 `❌ 解析失败 k 个:`（含文件:行号与错误片段）。
**只有这一关全绿，才算语法没问题。** 不要靠肉眼判断「应该能渲染」。

### 第二步：按错误/诉求修复

见下方「常见解析错误」对照表逐条修。修完**必须重跑 validate.mjs 复核**。

### 第三步：布局审计（单列 / 兄弟横排）

执行布局修复脚本（幂等，可重复跑）：

```bash
node scripts/fix.mjs <仓库根目录>
```

该脚本对每块图做结构分析，按下方「布局规约」自动改写方向，**不改动纯链/循环图**，并打印改动文件清单。
跑完同样用 `validate.mjs` 复核语法。

## 常见解析错误与修复（实战沉淀）

GitHub 的 mermaid 渲染器对语法比本地编辑器严格。以下为已踩过的坑：

| 症状 / 报错 | 根因 | 修复 |
|---|---|---|
| `Expecting 'SQE' ... got 'PS'`，箭头标签含括号 | 边标签 `\|HTTPS (内网)\|` **未加引号**，括号被当语法 | 改为 `\|"HTTPS (内网)"\|`；所有含 `()` `:` `/` `#` 等符号的标签统一加引号 |
| `subgraph` id 被当边端点：`EMP --> DESK` 且 `DESK` 是 `subgraph` | 子图被当作节点用在边里 | 把该子图改成**普通节点** `DESK["..."]`，或让边连到子图内的真实节点 |
| `Expecting ... got 'DIAMOND_START'` 或标签里出现 `{` | 节点标签内含 `{}` `[]` `"` 触发形状/字符串解析 | 标签内去掉 `{}` `[]` `"`，改用中文括号 `（）【】` 或文字描述 |
| 标签内 `data: [DONE]` 的 `]` 提前闭合标签 | `]` 被视为标签结束 | 标签内避免 `[` `]`，写成 `（DONE）` 或 `DONE` |
| 标签里 `search_manual(\"账户查询接口\")` 报错 | `\"` 转义在 mermaid 标签里**无效** | 去掉转义，改用单引号 `'账户查询接口'` 或中文引号 |
| 双向连线 `<->` 报 `got 'TAGSTART'` | mermaid 合法双向符号是 `<-->` | `<->` → `<-->` |
| `subgraph VOLS[""]` 报 `got 'SQE'` | 子图**空标签**非法 | 补一个标签，如 `subgraph VOLS["持久化数据卷"]` |

**通用防护**：全仓库扫描边标签，凡含特殊字符且未加引号的 `\|...\` 统一加引号（安全，不会破坏合法图）。

## 布局规约（兄弟节点横排）

mermaid 按「层级(rank)」排布，**同级(兄弟)节点是否横排取决于主方向**：

- `TB` / `TD` / `BT`：同级节点**横向并排** ✅
- `LR` / `RL`：同级节点**纵向堆叠** ❌（这是「兄弟节点没横排」的根因）

据此制定规则：

1. **含分叉/汇合（即有真实兄弟节点）的图 → `TB`**。这样兄弟节点横向展开，也不会变成单列。
2. **纯链 / 循环图（无兄弟节点）→ `LR`**。保持横向一行，避免退化成又高又窄的单列。
3. **有意纵向的图 → 保持 `TB` 不变**。例如章节明确写「请求流程（从上到下）」「数据流向（从下到上）」的图，纵向是语义，不要为了横排而改。
4. **子图内部**同样适用：子图 `direction LR/RL` 且内部有兄弟节点 → 改 `direction TB`；纯链子图（水平层带）保持 `direction LR` 以维持横向链。

### ⚠️ 关键陷阱：循环回边 ≠ 兄弟节点

ReAct 循环图（`A→B→C→D→E，D→B`）会让某节点 `indeg/outdeg ≥ 2`，**看起来像汇合/分叉**，但那是回到祖先的**回边(cycle)**，不是兄弟。若误判为兄弟而转 `TB`，会把本该横向的循环图又变回单列。

**判定「真实兄弟」的算法**（脚本已内置，勿用简单 `indeg>=2` 误判）：
节点 X 有兄弟，当且仅当存在两个父(或子) `p1,p2` 满足：
- `p1` 与 `p2` **互相不可达**（`reach(p1,p2)` 与 `reach(p2,p1)` 均为 false），且
- X **不能到达** `p1`/`p2`（排除回边）。

即：必须是两条**互不相关**的分支在同一层汇合/分叉，才算真实兄弟。

## 脚本说明

- `scripts/validate.mjs <repo>`：全量语法校验，退出码 0=全过 / 1=有错。
- `scripts/fix.mjs <repo>`：布局修复（顶层 LR+兄弟→TB；子图 direction LR+兄弟→TB）。幂等可重跑。

两脚本都递归扫描 `<repo>` 下所有 `.md`（跳过 `.git/`）。

## 提交纪律

- 修复后**必须**重跑 `validate.mjs` 确认 `✅ 全部通过` 再提交。
- 布局类改动单独提交，commit message 注明「style: ...」并说明改动依据（兄弟横排 / 单列优化）。
- 未追踪文件（如 `.docx`、`.opencode/settings.local.json`）不要纳入提交。

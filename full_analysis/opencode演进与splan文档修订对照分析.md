# opencode 演进与 splan 文档修订对照分析

> 分析日期：2026-09-01
> 分析对象：`/data/opencode`（上游 OpenCode + `opencode-session-mgmt` 定制）相对 `/data/splan` 银行业 AI 落地文档的演进
> 结论：splan 的「智能体开发框架（doc 5）」「研发智能助手（doc 6）」是对 `opencode-session-mgmt` 的银行业重述，但文档停留在 opencode 的早期版本；opencode 近期在「质量管控、研发工作流、人机协同、度量反馈、银行业覆盖层」五个方向有大量新增，splan 文档需要同步。

## 三、修订建议（优先级）

**P0（必须补，否则框架文档与上游严重脱节）— 落在 doc 5：**
1. 新增「十、AI 编码质量管控框架（四支柱）」：把制定规约/增强知识/智能协同/度量反馈对应到 Harness 的 Guardrails、Context7、工作流引擎、效能看板；并点明「银行业覆盖层规约」是 ① 的银行落地（引用 conventions 里的 6 个银行规约文件）。
2. 新增「十一、研发工作流引擎（sdlc / reqdoc 完成门禁）」：需求→设计→编码→测试→审查→提交，完成门控、AI 提议+人确认、审查为唯一不可 AI 自推阶段、提交唯一硬门禁。
3. 扩展「八、数字员工工作台」：新增 8.7「与 IDE 智能插件的互补分工（open_ide 文件锁）」，补双泳道图与混合开发「谁写的审谁」。

**P1（重要）— 落在 doc 5 / doc 6：**
4. 新增「十二、理解保障与逐段确认（监管可接手标准）」：comprehension 逐段确认、审查四清单（业务意图/逻辑可解释/行为可验证/设计推导）、一次通过率。
5. 新增「十三、度量反馈与 ROI（效能看板）」：会话→项目→组织三级、一次通过率/返工率/费用/提效%。

**P2（衔接性）— 落在 doc 2 / doc 1：**
6. doc 2 在「智能体开发框架」之后补一节「研发治理与质量管控层」，说明四支柱与银行覆盖层。
7. doc 1 在科技自我造血/成熟度模型处，补充「数字员工双泳道」与「四支柱质量管控」作为治理骨架。
